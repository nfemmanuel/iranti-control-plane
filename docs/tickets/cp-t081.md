## Description

CP-T073 (Phase 5, Wave 12) implemented the `POST /api/control-plane/instances/:name/upgrade` endpoint and added an Upgrade section inside the Instance Manager's instance detail (expanded) panel. That work is done and accepted.

The gap CP-T081 closes: the upgrade action is buried. It only appears when an operator expands an instance card, digs into the detail panel, and scrolls to the upgrade section. Meanwhile, the Health Dashboard version sync (CP-T078) will surface a prominent "Update available: v0.2.17" message — but clicking it does nothing.

This ticket promotes the upgrade action so that:
1. When CP-T078 shows "update available," an **Upgrade Iranti** button appears prominently in the Instance Manager header (not buried in the detail panel).
2. Clicking the button connects to the existing CP-T073 upgrade endpoint — no new backend work required.
3. Progress and result are shown inline, same as the existing CP-T073 implementation.

This is a frontend-only ticket. The backend upgrade endpoint is already complete.

---

## What to Build

### Frontend — Promoted Upgrade Action

**Where to add the button:**

In the Instance Manager view header area — the top of the page above the instance list, where the page title and any global actions sit. This is visible without expanding any instance card.

**Visibility condition:**

The Upgrade button is ONLY shown when:
- CP-T078 `version-sync` data indicates `upToDate === false` AND `latestVersion !== null`

When `upToDate === true` or version data is unavailable: the Upgrade button is hidden. This prevents operators from running an upgrade unnecessarily.

**Button label:** `Upgrade Iranti to v{latestVersion}`

**Button style:** Use `--color-warning` (amber-orange) to match the "update available" warning state — this is not a neutral action. A distinct "caution" visual style signals that this is an impactful action.

**Button flow:**

1. Operator sees "Update available: v0.2.17" in the Health Dashboard (CP-T078)
2. Operator navigates to Instance Manager
3. "Upgrade Iranti to v0.2.17" button is visible in the header
4. Clicking opens a confirmation modal:
   - Title: `Upgrade Iranti to v{latestVersion}?`
   - Body: `This will run iranti upgrade --restart for each running instance. Active agents will experience a brief interruption. This may take up to 60 seconds per instance.`
   - If multiple instances are running: list them in the modal
   - Buttons: Cancel / Upgrade
5. On confirm: call `POST /api/control-plane/instances/:name/upgrade` for the **primary/active instance** (or sequentially for all running instances if there are multiple)
6. Show an inline progress panel with the live output from the upgrade job (same as CP-T073 UI, reused or refactored into a shared component)
7. On success: show success message; refresh version sync data; button disappears (version is now up to date)
8. On failure: show failure state with output; offer "Try again"

**Multiple instances:**

If there are multiple instances configured, the upgrade applies to the **active/selected** instance by default. The modal informs the operator which instance is being upgraded. Upgrading all instances sequentially is a stretch goal — the primary deliverable is upgrading the active instance.

**Relationship to existing CP-T073 detail panel upgrade:**

The existing Upgrade section in the instance detail panel (CP-T073) should remain as-is. The CP-T081 promoted button is additive — it gives operators a faster path to the same action when an update is available. Both paths invoke the same backend endpoint.

If the CP-T073 detail panel upgrade section and the CP-T081 header button share progress UI components, refactor into a shared `UpgradeProgressPanel` component. Do not duplicate the polling logic.

## Acceptance Criteria

### AC-1 — Upgrade button only visible when update is available

The "Upgrade Iranti" button is only visible in the Instance Manager header when `version-sync` returns `upToDate: false` and `latestVersion` is not null. When up to date: button is not rendered (not hidden, not disabled — not rendered).

### AC-2 — Connects to existing CP-T073 upgrade endpoint

Clicking Upgrade triggers `POST /api/control-plane/instances/:name/upgrade` (the endpoint built in CP-T073). No new backend endpoint is required.

### AC-3 — Shows progress and result inline

After confirming the upgrade, an inline progress panel shows live output lines polled from `GET /api/control-plane/instances/:name/upgrade/:jobId`. Spinner while running, success message on completion, failure message with output on error.

### AC-4 — Version data refreshed after upgrade

After a successful upgrade, the control plane re-fetches `version-sync` data. If the upgrade succeeded and the instance restarted, `upToDate` should now be `true` and the Upgrade button should disappear.

### AC-5 — Confirmation modal shown before upgrade

A confirmation modal is shown with the instance name, target version, and interruption warning. Upgrade only starts after operator confirmation.

### AC-6 — tsc clean

`tsc --noEmit` passes with 0 errors in `src/client`.
