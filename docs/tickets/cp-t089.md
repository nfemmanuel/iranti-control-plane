# CP-T089 — Instance Create

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P0
**Status:** OPEN
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

The Instance Manager shows existing instances and their lifecycle but cannot create a new instance. Creating a second instance (for a team project, a staging environment, or parallel memory spaces) always requires the terminal:

```bash
iranti instance create local --port 3001 --db-url "postgresql://..." --provider mock
```

or the interactive setup wizard (`iranti setup`). Neither is available inside the control plane.

This is a P0 gap because onboarding a second project into Iranti requires creating a new instance — and the control plane should be the operator's one-stop interface for this.

---

## User Story

As an Iranti operator, I want to create a new Iranti instance from the Instance Manager, so that I can set up a second project or team memory space without using the terminal.

---

## Acceptance Criteria

1. Instance Manager has a "Create Instance" button in the header.
2. Clicking it opens a multi-step creation form:
   - Step 1: Instance name (alphanumeric + underscore, required), port (default: next available port after 3001)
   - Step 2: Database URL (full PostgreSQL connection string) — input field with placeholder and format hint; validation that it does not contain placeholder values
   - Step 3: Provider selection (dropdown: gemini, claude, openai, groq, mistral, ollama, mock) + provider API key (if remote provider selected)
   - Step 4: Review + Create
3. Port conflict detection: the form warns if the chosen port is already in use by another known instance.
4. On "Create", the backend calls `iranti instance create <name> --port <port> --db-url "<url>" --provider <provider>` as a subprocess, or writes the instance env file directly using the same file layout as the CLI.
5. After creation, the new instance appears in the Instance Manager list.
6. The created instance is in "stopped" state — a "Start" button is immediately available.
7. Error handling:
   - Invalid database URL format — form-level validation
   - Instance name already exists — form error "An instance named X already exists"
   - Port conflict — form warning with suggested alternative
   - CLI/write failure — toast error with raw error detail
8. Backend route: `POST /api/control-plane/instances` — body: `{ name, port, dbUrl, provider, providerKey? }`
9. The backend adds the new instance to the instance registry (same `~/.iranti/instances/` structure as the CLI creates).

---

## Implementation Notes

- The backend can delegate to `iranti instance create` as a subprocess (same pattern as `lifecycle.ts` delegates to `iranti run`), or replicate the file-write logic if the CLI is not available as a subprocess.
- Port availability check: scan known instance env files for `IRANTI_PORT` conflicts before accepting the request.
- Database URL validation: same rules as `iranti-cli.ts` configure — reject placeholders (`yourpassword`, `replace_me`, etc.).
- After creation, the instance should appear immediately in `GET /api/control-plane/instances`.
