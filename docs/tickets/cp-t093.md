# CP-T093 — MCP and Hook Visibility

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P1
**Status:** PM-ACCEPTED 2026-03-22
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

Operators using Claude Code, Codex, or other MCP clients have no visibility in the control plane into:
- What MCP servers are registered per project (`.mcp.json` full content)
- What tools are exposed by each MCP server (specifically the Iranti MCP tools)
- What hooks are configured (`.claude/settings.local.json` hook events and commands)
- Whether these configurations are healthy or broken

This is a diagnostic blind spot. When hooks fail silently or MCP tools aren't available, operators have nowhere to start in the control plane.

This ticket is narrower than CP-T092 — it covers general MCP/hook visibility across all projects as a dedicated view, separate from the per-project Claude integration panel.

---

## User Story

As an Iranti operator, I want a dedicated view of all MCP server registrations and Claude Code hook configurations across my bound projects, so that I can quickly diagnose MCP or hook issues without inspecting files manually.

---

## Acceptance Criteria

1. A new "Integrations" view (or section within the Instance Manager) lists all bound projects with their integration state:
   - MCP: registered servers count, whether `iranti` is present, MCP file status
   - Hooks: hook events configured, commands, hook file status
2. Each project row is expandable to show:
   - Full MCP server list from `.mcp.json` (server name, command, args)
   - Full hook list from `.claude/settings.local.json` (event, matcher, command)
3. Known issues are highlighted inline:
   - Iranti MCP server missing
   - Hook command references a path that doesn't exist
   - Hook command uses a stale `iranti` binary path
   - `.mcp.json` is invalid JSON
4. The Iranti MCP tool list is shown for each project where Iranti MCP is registered:
   - `iranti_handshake`, `iranti_attend`, `iranti_observe`, `iranti_query`, `iranti_search`, `iranti_write`, `iranti_ingest`, `iranti_relate`, `iranti_who_knows`
   - Each tool shows: name, description (brief), whether it's available based on current connectivity
5. "Quick Fix" actions per issue:
   - "Scaffold integration" → redirects to CP-T092 scaffold action
6. Backend route: `GET /api/control-plane/integrations` — returns integration summary across all projects

---

## Implementation Notes

- This view can reuse the same backend logic as CP-T092 but aggregates across all projects rather than one.
- MCP tool list can be derived from the known Iranti MCP tool definitions (static list — no need to spawn the MCP server).
- Hook validation: check that `iranti` command is on PATH and that the hook commands are syntactically correct (basic shell parse).
- Codex integration (registered MCP in Codex global config) is out of scope for this ticket — that is CP-T095.
