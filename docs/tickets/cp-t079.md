# CP-T079 — Iranti Install Detection

**Type:** Feature (Backend + Frontend)
**Priority:** P1
**Assigned:** backend_developer (detection) + frontend_developer (UI)
**Phase:** 6 (Wave 15)
**Status:** OPEN
**Epic:** CP-E019 (Lifecycle Management)
**Depends on:** Nothing hard — but CP-T076 (palette) should be done first for visual correctness

---

## Description

The control plane currently assumes Iranti is already installed and running. It has no concept of "Iranti is not installed on this machine." This creates a frustrating experience for new users who open the control plane before installing Iranti: all health checks fail, the Instance Manager shows nothing, and there is no guidance.

This ticket makes the control plane aware of whether the `iranti` CLI is available on the system PATH, and surfaces that state clearly in the Instance Manager. It is the prerequisite for CP-T080 (Process Lifecycle Controls) and CP-T083 (Guided Setup Wizard).

---

## What to Build

### Backend — Install State Detection

**Detection logic:**

Run a platform-appropriate PATH check to detect the `iranti` CLI:
- Unix (macOS / Linux): `which iranti`
- Windows: `where iranti`

If the command exits with code 0 and returns a non-empty path: Iranti is installed. Extract the path.

If found, also extract the version by running `iranti --version` as a subprocess and parsing the output. The output format is expected to be `iranti/X.Y.Z` or simply `X.Y.Z` — handle both.

**Expose as endpoint:**

```
GET /api/control-plane/install-state
```

**Response:**

```typescript
interface InstallStateResponse {
  installed: boolean;
  version: string | null;         // semver string if installed, null if not
  executablePath: string | null;  // absolute path from `which`/`where`
  checkedAt: string;              // ISO timestamp
}
```

**Platform handling:**
- Use `process.platform` to switch between `which` and `where`
- On Windows: `where iranti` may return multiple paths; use the first one
- Wrap the subprocess call in a try/catch — if the subprocess itself throws (e.g., `which` not found on some embedded systems), return `installed: false` gracefully
- Timeout: 3 seconds maximum for the subprocess — beyond that, treat as not found

**Optionally:** Also integrate `installState` into the existing health endpoint response as an additional field, so the Health Dashboard can show install state without a separate fetch. This is a stretch goal — the dedicated endpoint is the primary deliverable.

**TypeScript:** Clean. No `any`.

### Frontend — Install State in Instance Manager

**Where to display:**

In the Instance Manager view, add an "Iranti CLI" status section at the top of the page (above the instance list). This appears regardless of whether instances are configured.

**Layout:**

When installed:
```
Iranti CLI  ✓ Installed — v0.2.16
Path: /usr/local/bin/iranti
```

When not installed:
```
Iranti CLI  ✗ Not found
Install with:  npm install -g iranti  [Copy]
```

**Copy button:**
- Copies the command `npm install -g iranti` to the clipboard
- Shows a brief "Copied!" confirmation for 2 seconds

**When not installed:**
- The Instance Manager should show a clear guidance state instead of an empty instance list with cryptic errors
- The empty state message should read: "Iranti is not installed on this machine. Install it to create and manage instances."
- This state is picked up by CP-T083 (Guided Setup Wizard) — when not installed, the wizard takes over the full screen

## Acceptance Criteria

### AC-1 — PATH detection works on Windows and Unix

On macOS/Linux: `which iranti` is used. On Windows: `where iranti` is used. The correct command is selected based on `process.platform`. Detection result is accurate (returns `installed: true` when `iranti` is on PATH, `installed: false` when it is not).

### AC-2 — Version extraction from `iranti --version` output

When installed, `iranti --version` is called and the semver version string is extracted and returned in `version`. Handles both `iranti/0.2.16` and bare `0.2.16` output formats.

### AC-3 — UI surfaces install state clearly

The Instance Manager shows a clear install state section: green "Installed" badge with version when installed, red "Not found" badge with copy-button install command when not installed.

### AC-4 — Graceful when iranti not installed

`GET /api/control-plane/install-state` returns HTTP 200 with `{ installed: false, version: null, executablePath: null, ... }` when iranti is not on PATH. No 500 errors, no unhandled exceptions.

### AC-5 — Copy button works

Clicking the copy button in the "not installed" state copies `npm install -g iranti` to the clipboard and shows a brief "Copied!" confirmation.

### AC-6 — tsc clean

`tsc --noEmit` passes in both `src/server` and `src/client` with 0 errors.
