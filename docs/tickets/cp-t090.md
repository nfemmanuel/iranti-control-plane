# CP-T090 — Instance Configure (Edit Env Settings)

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P1
**Status:** OPEN
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

The Instance Manager can start, stop, and upgrade instances, but cannot reconfigure them. Changing a database URL, port, or provider for an existing instance requires `iranti configure instance <name>` or hand-editing the instance env file.

This is a common operation: instances get new DB URLs when PostgreSQL is migrated, ports conflict after system changes, and providers change as operators evaluate alternatives.

---

## User Story

As an Iranti operator, I want to edit an existing instance's configuration (port, database URL, provider) from the Instance Manager, so that I can reconfigure an instance without the terminal.

---

## Acceptance Criteria

1. Each instance in the Instance Manager has a "Configure" button (gear icon) that opens an instance configuration panel.
2. The panel shows current values (from the instance env file) for:
   - Port (`IRANTI_PORT`)
   - Database URL (`DATABASE_URL`) — displayed masked (scheme://user:****@host:port/db)
   - Provider (`LLM_PROVIDER`)
3. Each field is editable. "Cancel" discards changes. "Save" submits the update.
4. Validation: same rules as CP-T089 (no placeholders, port conflict check, valid DB URL format).
5. After saving, if the instance is currently running, the panel shows: "Restart required for changes to take effect." with a "Restart Now" button.
6. Backend route: `PATCH /api/control-plane/instances/:name` — body: `{ port?, dbUrl?, provider?, providerKey? }`
7. The backend writes the updated values to the instance env file using the same merge strategy as `iranti configure instance` (read existing, update target vars, write back).
8. The instance list refreshes after a successful update.

---

## Implementation Notes

- The "Restart required" warning should appear only if the instance was running at save time (check runtime.json or health probe).
- DB URL masking in display: parse the URL and replace password with `****`. Do not expose raw DB URL in GET responses — only show masked form.
- Port changes require restart to take effect. DB URL changes also require restart. Provider changes take effect immediately on next Staff operation (no restart required for provider, but may require restart for the change to propagate — mark informational).
