# CP-T086 — Provider Default + Fallback Chain Configuration

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P0
**Status:** OPEN
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

Iranti supports:
- `LLM_PROVIDER` — the default provider for all tasks
- `LLM_PROVIDER_FALLBACK` — an ordered comma-separated fallback chain for HA / rate-limit handling (e.g. `openai,groq,mistral,mock`)

Neither of these is configurable from the control plane. Operators who want to configure high-availability fallback or switch their default provider must hand-edit the instance `.env` file or use the CLI.

The Provider Manager currently shows the active provider and reachability but has no write surface for default or fallback configuration.

---

## User Story

As an Iranti operator, I want to set the default provider and configure the fallback chain from the Provider Manager, so that I can manage provider routing without editing env files.

---

## Acceptance Criteria

1. Provider Manager shows the active `LLM_PROVIDER` prominently with a "Change Default Provider" selector (dropdown with known providers: gemini, claude, openai, groq, mistral, ollama, mock).
2. Changing the default provider writes `LLM_PROVIDER` to the instance env and triggers a reachability refresh.
3. Provider Manager shows the current `LLM_PROVIDER_FALLBACK` chain — displayed as an ordered list of providers (e.g. "openai → groq → mock").
4. "Edit Fallback Chain" opens an inline editor:
   - ordered list of providers
   - drag-reorder or up/down arrows
   - add provider to chain
   - remove provider from chain
   - "Clear fallback chain" action
5. On save, the backend writes `LLM_PROVIDER_FALLBACK` as a comma-separated string to the instance env.
6. If no fallback chain is configured, the UI shows "No fallback configured" (not an error).
7. Backend routes:
   - `PUT /api/control-plane/providers/default` — set `LLM_PROVIDER` (body: `{ provider: string }`)
   - `PUT /api/control-plane/providers/fallback` — set `LLM_PROVIDER_FALLBACK` (body: `{ chain: string[] }`)
   - `DELETE /api/control-plane/providers/fallback` — clear fallback chain
8. The `GET /api/control-plane/providers` response should include `defaultProvider` and `fallbackChain` fields.

---

## Implementation Notes

- Same env-file write pattern as CP-T085.
- `fallbackChain` in response: parse `LLM_PROVIDER_FALLBACK` env var and return as `string[]`.
- Validation: accepted providers are `gemini`, `claude`, `openai`, `groq`, `mistral`, `ollama`, `mock`. Unknown values produce a warning but are not blocked (future providers may be added upstream).
- The default provider and fallback chain should be shown on the Provider Manager's main screen, not buried in a settings panel.
