# CP-T095 — Codex Integration Manager

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P2
**Status:** PM-ACCEPTED 2026-03-22
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

`iranti codex-setup` (alias: `iranti integrate codex`) registers Iranti with Codex globally. There is no control plane surface for:
- Checking whether Codex is installed on this machine
- Viewing whether Iranti is registered with Codex and in what form
- Running `iranti codex-setup` from the UI
- Removing the Codex registration

Codex users have zero visibility into their Codex integration state from the control plane.

---

## User Story

As an Iranti operator using Codex, I want to see and manage the Codex integration state from the control plane, so that I can set up or repair the Codex integration without the terminal.

---

## Acceptance Criteria

1. A "Codex Integration" section appears in the Instance Manager (or Integrations view).
2. The section shows:
   - Whether Codex is detected on this machine (check `codex` binary on PATH)
   - Whether Iranti is registered with Codex (read the Codex MCP registration file)
   - The registered project path, if any
3. "Register with Codex" action calls `iranti codex-setup` as a subprocess and refreshes the state.
4. "Remove Codex Registration" action calls `iranti uninstall --target codex` or equivalent.
5. Error state: "Codex not found on PATH. Install Codex first." with a link to Codex documentation.
6. Backend routes:
   - `GET /api/control-plane/integrations/codex` — returns: `{ codexInstalled, irantiRegistered, registeredProjectPath }`
   - `POST /api/control-plane/integrations/codex` — runs `iranti codex-setup`
   - `DELETE /api/control-plane/integrations/codex` — removes registration

---

## Implementation Notes

- Codex detection: `which codex` (Unix) or `where codex` (Windows).
- Codex MCP registration location: check the Codex global config file for an Iranti entry (same logic as `iranti uninstall --all` uses when removing Codex registration).
- The backend delegates to CLI subprocesses for register/unregister, same as the lifecycle endpoints.
- This is P2 because Codex users are a smaller subset than Claude Code users. Build after CP-T092.
