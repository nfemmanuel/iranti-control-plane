# CP-T096 — Attendant Debug Tools (Manual Handshake/Attend from UI)

**Phase:** 7 — Operator Configuration Management
**Epic:** CP-E017
**Priority:** P2
**Status:** PM-ACCEPTED 2026-03-22
**Owner:** backend_developer, frontend_developer
**Created:** 2026-03-22

---

## Problem

`iranti handshake --task "<text>"` and `iranti attend "<query>"` are operator debug tools for understanding what the Attendant is doing — what working memory brief it would generate, what facts it would retrieve for a given query.

These are used when debugging why memory isn't loading correctly for an agent. Currently, operators must use the terminal. The control plane has no surface for this.

---

## User Story

As an Iranti operator debugging memory retrieval issues, I want to run manual Attendant handshake and attend queries from the control plane, so that I can understand what the Attendant would surface for a given agent and task without using the terminal.

---

## Acceptance Criteria

1. A "Attendant Debug" panel exists within the Diagnostics view (or as a sub-section of the Health dashboard).
2. The panel has two tools:

**Manual Handshake:**
- Input: agent ID, task description (text area)
- "Run Handshake" button
- Output: the brief that the Attendant would generate — displayed as formatted JSON with:
  - working memory items (entity, key, summary, confidence)
  - session recovery state (if any)
  - inferred task type
- Clearly labeled as "Attendant Debug Tool — this shows what an agent would see on handshake"

**Manual Attend:**
- Input: agent ID, query text, optional context text (text area)
- "Run Attend" button
- Output: retrieved memory blocks relevant to the query, with entity + key + confidence displayed

3. Both tools call the Iranti HTTP API (`POST /memory/handshake` and `POST /memory/attend`) through the control plane backend proxy.
4. Results are displayed in a readable structured format, not raw JSON dump (though a "View raw JSON" toggle is available).
5. Error states:
   - "Iranti not running" — prompt to start the instance
   - "Invalid agent ID" — form validation
6. Backend routes:
   - `POST /api/control-plane/debug/handshake` — proxies to `/memory/handshake` on the active Iranti instance
   - `POST /api/control-plane/debug/attend` — proxies to `/memory/attend`

---

## Implementation Notes

- This is a proxy — the control plane backend calls the Iranti HTTP API with the Iranti API key from the instance env.
- The handshake and attend endpoints are part of the Iranti memory API (`/memory/*` routes with `memory:read` scope).
- The CP needs a `memory:read` scoped key for the active instance to proxy these calls.
- This is P2 because it is a power-user debug tool, not a daily operational need. It should be visible but not prominent.

---

## Dependencies

- Iranti HTTP API: `POST /memory/handshake`, `POST /memory/attend`
- The active instance must be running and reachable
- The CP backend needs a `memory:read` scoped API key for the active instance
